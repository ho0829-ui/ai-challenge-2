# 03. 초기 접근과 개선의 출발점

## 초기 발표에서 확인되는 흐름

초기 발표는 Qwen2.5-VL 기반 이전 최고 Public LB를 0.90으로 기록합니다. 이어 Qwen3-VL 단일 8B·768 시각 토큰 validation 0.955, 8B·768과 4B·1280 앙상블 validation 0.9604를 제시합니다. **첫 점수는 LB, 나머지는 내부 validation**이므로 같은 평가 조건의 0.90 → 0.9604 개선이라고 표현하지 않습니다.

| 초기 자료의 항목 | 확인되는 내용 | 확인되지 않는 내용 |
|---|---|---|
| Qwen2.5-VL baseline | 이전 최고 LB 0.90 | 정확한 모델 ID·학습 코드·분할·세부 하이퍼파라미터 |
| Qwen3-VL 단일 뷰 | 8B·768 토큰 validation 0.955 | 그 실행의 예측 배열·분모 |
| 초기 두 모델 결합 | 8B·768 + 4B·1280, validation 0.9604 | 해당 시점의 가중치 탐색 전체 코드·출력 |

근거: `D024_천천히꾸준히김상엽_base.pptx` 슬라이드 6. 제공된 두 노트북은 후속 0.97140 단계이며 Qwen2.5 baseline 구현은 포함하지 않습니다.

## 초기 수정의 다섯 축

초기 발표 슬라이드 5는 dev 다수결 데이터 추가, 시각 토큰 예산 증가, 확률 50:50에서 로그확률·온도 보정·비율 탐색으로의 변경, 실행 환경 변경, 리사이즈 캐시를 나열합니다. 이들은 초기 단계의 설명이며 후속 코드에서 모두 동일하게 유지된 것은 아닙니다.

특히 코드 전용 셀 16은 계열 내부·계열 간 **고정 균등 가중치**를 사용합니다. 초기의 “비율 자동 선택”과 제공 노트북의 최종 결합 방식을 하나의 알고리즘처럼 쓰면 안 됩니다. 초기 발표의 8B 일부 상위 층만 학습했다는 설명도 코드 전용 셀 7의 LoRA 정규식에는 층 제한으로 구현되어 있지 않습니다.

초기 발표 슬라이드 3은 8B·256과 4B·640의 비교에서 +1.5%p라고 기록합니다. 모델 크기와 입력 예산을 동시에 바꾼 비교이므로 입력 해상도 하나의 인과 효과로 분리할 수 없습니다. 이후 회고록에서는 2048/3072 확장에 이득이 없었다고 기록합니다. 초기의 확대 효과와 이미 충분한 입력 이후의 포화는 다른 단계의 관찰입니다.

## 속도와 환경을 읽는 방법

초기 발표 슬라이드 2는 6,738문항을 15분 내 채점, 언어 선형층 LoRA와 시각 타워 동결, 약 1% 파라미터 학습을 설명합니다. 슬라이드 5는 RTX 5060 Ti 16GB에서 Colab 96GB 환경으로 옮겼다고 기록합니다. 후속 노트북 메타데이터에는 Colab GPU 힌트가 있으나 실제 장치 출력과 설치 버전이 저장되지 않았습니다.

따라서 처리 시간과 장치 정보는 **발표 기록**으로만 인용합니다. 현재 환경에서 측정한 값, 모든 뷰가 같은 속도로 실행된다는 보장, 전체 실험 소요 시간으로 확장하지 않습니다. 정확한 GPU 모델·CUDA 버전·라이브러리 조합·실험별 시간은 확인 필요입니다.

## 이 단계에서 다음으로 넘어간 질문

“단독 모델의 점수를 더 올릴 것인가, 기존 모델이 틀리는 문항을 다른 뷰가 맞히게 할 것인가?”가 후속 실험의 중심입니다. 같은 LoRA를 다른 입력 예산으로 재추론해 Q2·Q3를 만들고, 학습하지 않은 다른 모델 계열을 추가하는 방향으로 확장했습니다. 다음 [모델 문서](04_model.md)와 [앙상블 문서](05_ensemble.md)는 그 역할을 구분합니다.
