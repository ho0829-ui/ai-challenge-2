# 05. 정확도와 다른 오답을 함께 보는 앙상블

## 1. 왜 여러 뷰를 묶었는가

뷰는 모델 ID만을 뜻하지 않습니다. 같은 Qwen LoRA를 다른 시각 토큰 예산으로 추론한 Q·Q2·Q3도 서로 다른 뷰입니다. 하나의 뷰가 잘 맞히더라도 기존 앙상블이 틀린 문항을 같이 틀리면 추가 기여가 작습니다. 반대로 정확도가 낮은 뷰라도 기존 오답을 고치는 정보가 있을 수 있습니다. 실제 채택은 그 이득과 새 오답의 비용을 함께 비교해야 합니다.

회고록은 학습을 최소화하고 추론·앙상블에 더 집중한 이유를 데이터가 아직 절반 남아 있다는 판단으로 설명합니다. 이는 작성자의 전략 해석입니다. 학습이 언제나 과적합을 일으킨다는 보편 법칙이나 미공개 데이터 분포의 확인으로 확장하지 않습니다.

근거: `VQA회고록.md` §1, 초기 발표 슬라이드 4.

## 2. 초기 가설: 서로 다르게 틀리는 뷰를 찾자

같은 검증 문항에서 뷰 v의 오답 인덱스 집합을 `E_v={i: argmax p_v(i) ≠ y_i}`로 놓습니다. 두 뷰의 오답 Jaccard 유사도는 다음과 같습니다.

$$J(E_u,E_v)=\frac{|E_u\cap E_v|}{|E_u\cup E_v|}.$$

값이 클수록 오답 집합이 겹칩니다. 이는 확률 예측의 Pearson 상관계수나 오답의 인과 원인이 아닙니다. 두 집합이 모두 비면 분모가 0입니다. 제공 자료에는 Jaccard 계산 코드가 없어 당시의 빈 집합 처리를 확인할 수 없습니다. 재실험에서는 그 경우를 `NA`로 표기하고 평균에서 제외하는 등의 규칙을 먼저 정해야 합니다. 한 집합만 비면 합집합이 비지 않으므로 J=0입니다.

회고록은 14개 뷰에서 학습 여부가 같은 쪽 0.509, 다른 쪽 0.273을 기록합니다. 최종 발표 슬라이드 3은 전자를 학습↔학습, 후자를 학습↔무학습으로 설명합니다. 회고록 본문에는 무학습끼리 0.325라는 별도 값도 있습니다. “같은 쪽”의 집계 범위를 임의로 합치지 않습니다. 백본 비교는 같은 쪽 0.376, 다른 쪽 0.287입니다.

두 격차 0.236과 0.089의 비가 약 2.6이라는 기록은 **이 표의 수치 비교**입니다. 학습 여부가 백본보다 항상 2.6배 더 중요하다는 결론은 아닙니다. 초기 비교에 학습한 Qwen과 무학습 타 모델이 함께 있어서 학습 여부·모델 구조·정확도가 혼재했습니다. 낮은 Jaccard만 보고 선택하면 오답이 많은 낮은 정확도 모델을 과대평가할 수도 있습니다.

근거: 회고록 §1 “비상관성을 실제로 재봤습니다”, 최종 발표 슬라이드 3. 원시 오답 배열은 제공되지 않았습니다.

## 3. 후속 비교가 초기 해석을 바꿨다

같은 Gemma 26B-A4B를 학습 전후로 비교한 기록은 단독 validation 0.9583 → 0.9650, 학습 Qwen 5뷰와의 평균 겹침 0.294 → 0.345입니다. 더 닮게 틀리게 됐지만 단독 정확도도 올랐습니다. 최종 구성에서는 Gemma LoRA를 넣고 VARCO를 뺐으며 Public LB가 +0.0024로 보고됩니다.

이 LB 변화는 **Gemma 학습 뷰 추가 + VARCO 제외 + 3계열에서 4계열로 지분 변경**을 포함한 비교입니다. 학습만의 인과 효과로 분리할 수 없습니다. Gemma를 학습했더니 항상 다양성이 줄어든다거나 성능이 오르는 법칙을 얻은 것도 아닙니다.

VARCO 후속 LoRA는 단독 0.8967 → 0.9150, 겹침 증가 +0.085, 앙상블 −2문항으로 보고됩니다. 최종 발표 슬라이드 3은 겹침 0.194 → 0.279를 제시하고, 회고록의 전체 뷰 평균 0.215는 별도 비교 범위입니다. 두 평균을 하나의 전후 쌍으로 사용하지 않습니다. 정확도가 올라도 기존 앙상블에 더 유사해지는 비용이 더 클 수 있다는 사례입니다.

근거: 회고록 §1 “그 결론에는 조건이 붙습니다”, 최종 발표 슬라이드 3·6. Gemma·VARCO LoRA의 실행 코드와 배열은 미제공입니다.

## 4. 보기 순서 TTA는 실제로 무엇을 평균하는가

TTA(Test-Time Augmentation)는 추론 입력을 변형하고 예측을 합치는 방법입니다. 여기서는 주로 이미지 회전·반전이 아니라 **보기의 순환 순서 변경**입니다. 화면 위치 j에 원래 보기 `π_s(j)=(j+s) mod 4`를 표시하고, 화면 위치의 점수를 원래 보기 위치로 돌려놓습니다.

Qwen `predict`는 `s=0..n_tta-1`을 씁니다. 따라서 TTA 2는 s=0,1입니다. Gemma `gpredict`는 `[0,2,1,3][:n_tta]`, `gpredict_b`는 `[0,2][:n_tta]`라서 TTA 2는 s=0,2입니다. VARCO는 `[0,2,1,3]` 중 설정 횟수이며 중간 채택 설정은 TTA 1입니다. 모두 동일한 두 순열이라고 설명하면 틀립니다.

각 변형에서 네 로짓의 `log_softmax`를 구한 뒤 코드의 `agg[:, perm] += lp`로 원래 위치에 더합니다. 원래 보기 c에 복원된 확률을 p^(s)(c)라 하면 뷰 출력은 다음과 같습니다.

$$p_v(c)=\operatorname{softmax}_c\left(\frac{1}{S}\sum_{s=1}^{S}\log p_v^{(s)}(c)\right).$$

확률의 산술평균이 아니라 로그확률 평균, 즉 정규화된 기하평균입니다. 같은 이미지를 유지하므로 순서 편향을 줄이려는 목적이지만 개선은 보장되지 않습니다. 부록은 TTA2가 단일 순서보다 낮았던 비교도 기록합니다.

근거: 코드 전용 셀 8·12·14·15; 설명 노트북 셀 23. G26L TTA는 최종 발표의 설정 기록만 있고 구현은 없습니다.

## 5. 온도 보정과 실제 결합 식

Calibration은 확신과 실제 정답 빈도가 어울리는지를 다루는 개념입니다. Temperature scaling은 점수의 날카로움을 온도 T로 조절합니다. 제공 코드에서는 원래 전체 어휘 로짓이 아니라 **네 선택지에 대해 TTA까지 집계한 확률**의 로그를 사용합니다.

`L_v(c)=log(clip(p_v(c),1e-8,1))`라 하면, 뷰 보정 확률은 다음과 같습니다.

$$q_v(c;T_v)=\operatorname{softmax}_c(L_v(c)/T_v).$$

`fitT`는 validation 정답에 대한 평균 negative log likelihood를 최소화합니다. `minimize_scalar(method="bounded")` 범위는 `[0.3,5.0]`이고 손실 계산에서 확률을 `[1e-15,1]`로 다시 잘라 log를 취합니다. 양의 T만 사용하므로 단독 뷰 내 argmax는 보통 바뀌지 않지만 다른 뷰와 섞는 상대 확신은 바뀝니다. T>1은 완만하게, T<1은 더 날카롭게 만듭니다.

중간 코드에서 계열 f의 뷰 집합을 V_f라 하면 `w_v=1/(|F|×|V_f|)`이고 다음 식으로 결합합니다.

$$P(c)=\operatorname{softmax}_c\left(\sum_v w_v\log\big(\operatorname{clip}(q_v(c;T_v),10^{-8},1)\big)\right).$$

수치 안정화를 위한 clip을 무시하면 `P(c) ∝ ∏_v q_v(c)^{w_v}`입니다. 로그확률 결합이 무조건 과신에 덜 끌린다는 보장은 없습니다. 과하게 작은 확률도 강한 영향을 줄 수 있어 실제로 온도 보정을 함께 검토해야 합니다.

설명 노트북 셀 20은 Qwen T 0.75~1.04, 무학습 Gemma T 3.36, 보정 제거 시 −3문항을 보고합니다. 실제 온도 출력·배열은 없으므로 기록값으로만 사용합니다. 최종 발표 슬라이드 5의 “5분할 교차 적합”은 제공 `fitT`/결합 셀에 구현되어 있지 않습니다. 제공 코드가 out-of-fold 보정을 수행한다고 쓰지 않습니다.

근거: 코드 전용 셀 16, 설명 셀 20·21, 최종 발표 슬라이드 5.

## 6. 중간 구성과 최종 기록의 가중치

| 구성 | Q / Q2 / Q3 각각 | HR / HR2 각각 | VC | G26B | G26L |
|---|---:|---:|---:|---:|---:|
| 제공 코드 3계열 | 1/9 | 1/9 | 1/9 | 1/3 | 없음 |
| 회고록·최종 발표 4계열 | 1/12 | 1/8 | 제외 | 1/4 | 1/4 |

중간 HR 계열은 HR·HR2·VC를 묶습니다. “계열”은 이 프로젝트의 **집계 그룹**이고 엄밀한 백본 분류는 아닙니다. 최종 HR에서는 VC가 빠지고, G26L이 별도 GL 계열로 1/4을 받습니다. 최종 지분의 합은 `3×1/12+2×1/8+1/4+1/4=1`입니다.

노트북이 주장한 “3계열이 최적”과 회고록의 “4계열이 유리”는 동일 후보에서의 영구적 결론이 아닙니다. Gemma LoRA가 없는 중간 단계와 그 뷰가 생긴 후의 후보 구성이 다릅니다. 최종 자료는 같은 결합 원리를 설명하지만 최종 실행의 온도·확률·코드가 없으므로 위 식이 G26L까지 그대로 적용됐는지는 완전한 코드 검증을 할 수 없습니다.

근거: 코드 전용 셀 16, 설명 셀 1·20·21, 회고록 §2, 최종 발표 슬라이드 2.

## 7. 배운 점과 평가 한계

“다양할수록 좋다” 또는 “학습하면 상관 때문에 나쁘다”로 결론을 줄이면 Gemma·VARCO의 다른 결과를 설명하지 못합니다. 후보의 정확도, 기존 오답과의 겹침, 보정 후 확신, 바뀌는 지분을 함께 보고 **같은 문항에서 고침과 망침**을 측정하는 것이 더 유용합니다.

600행 내외의 같은 validation에서 입력·뷰·온도·가중치를 반복 선택하면 선택 편향이 생깁니다. Public LB를 반복 피드백으로 사용해도 Public 평가에 적응할 위험이 있습니다. 향후에는 이미지 그룹을 유지한 별도 최종 holdout이나 nested 평가, 같은 분할의 paired 비교와 신뢰구간을 계획할 수 있습니다. 이 계획은 아직 실행하지 않았습니다. 결과를 일반화하려면 더 독립적인 평가가 필요합니다.
