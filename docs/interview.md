# 면접 설명과 스스로 풀어볼 질문

이 문서는 원본 프로젝트를 설명하기 위한 초안입니다. 원본 작성자는 김상엽이며 초기 발표에 팀원 이름이 있습니다. **개인별 담당 역할·기여는 확인되지 않았습니다.** 아래 답변의 “프로젝트에서”를 본인의 역할 주장으로 바꾸려면 실제 참여 사실과 산출물을 먼저 확인해야 합니다.

## 30초 설명

“한국어 간판과 메뉴판 이미지를 보고 네 보기 중 정답을 고르는 VQA 프로젝트입니다. Qwen3-VL의 LoRA 학습 뷰와 Gemma의 학습·무학습 뷰를 결합했고, 단독 점수뿐 아니라 서로 어떤 문항을 다르게 틀리는지 확인했습니다. 최종 기록은 내부 검증 0.9767, Public LB 0.97378입니다. 정확도와 다양성의 균형, 좁은 오류 유형의 개입, 반복 튜닝의 한계를 배웠습니다.”

근거·범위: [README 결과표](../README.md), [앙상블](05_ensemble.md). 기록된 결과를 설명하는 것이며 개인 수행 역할과 재현 성공을 주장하지 않습니다.

## 2분 설명

“입력은 이미지·한국어 질문·네 보기이고 답은 a/b/c/d입니다. 모델이 긴 설명을 생성하도록 하지 않고 마지막 위치의 네 보기 토큰 로짓을 직접 채점했습니다. 같은 이미지에 여러 질문이 있을 수 있어 이미지 바이트의 MD5 그룹으로 내부 검증을 분리하고, dev의 다수결 라벨도 검증 이미지와 겹치는 것을 제외했습니다.

Qwen3-VL 8B와 4B에 LoRA를 사용하고 같은 어댑터를 여러 시각 입력 예산으로 추론해 뷰를 만들었습니다. 보기 순서 TTA에서는 순환시킨 선지의 점수를 원래 위치로 돌려놓은 뒤 로그확률을 평균했습니다. 뷰마다 온도를 맞추고 계열 내부를 평균해 한 계열의 뷰 수가 많다는 이유만으로 전체를 지배하지 않도록 결합했습니다.

핵심 질문은 정확도가 높은 뷰가 기존 앙상블을 얼마나 보완하는지였습니다. 초기 오답 Jaccard 비교는 학습 여부와 백본이 혼재했지만, 후속 Gemma 학습 전후 비교에서 단독 정확도와 겹침이 동시에 증가하는 결과가 기록됐습니다. 최종 변경은 Gemma LoRA 추가와 VARCO 제외를 포함하므로 학습만의 효과로 말하지 않습니다.

회고록과 최종 발표의 7뷰·4계열은 검증 0.9767, Public LB 0.97378입니다. 제공 노트북은 그 이전 0.97140·3계열이라 최종 재현 코드가 완비된 것은 아닙니다. 남은 오답에는 판독 실패 외에 모호성과 라벨 의심도 기록돼 있습니다. 다음에는 독립 holdout과 복합 변경을 분리한 ablation으로 결과를 더 엄밀히 검증하겠습니다.”

연결: [데이터](02_data.md), [모델](04_model.md), [앙상블](05_ensemble.md), [오답](07_error_analysis.md), [근거의 한계](sources.md).

## 예상 질문과 답변

### VQA와 VLM의 차이는 무엇인가요?

VQA는 이미지에 대한 질문에 답하는 과제이고 VLM은 시각·언어 정보를 처리하는 모델입니다. 여기서는 VLM의 다음 토큰 점수를 활용해 4지선다 VQA를 풀었습니다. Qwen과 Gemma가 모델, 한국어 장면 텍스트 문항이 과제입니다. [문제](01_problem.md), 코드 전용 셀 8·12.

### 왜 문장을 생성하지 않고 로짓을 읽나요?

정답 형식이 네 보기 중 하나이므로 네 토큰 점수를 직접 비교하면 출력 파싱 실패를 줄일 수 있습니다. 코드가 각 보기가 한 토큰인지 검사하고 left padding을 써 마지막 위치를 통일합니다. 추론은 안정적인 형식이어도 오답을 낼 수 있습니다. [문제](01_problem.md), [모델](04_model.md), 코드 전용 셀 7·8.

### LoRA의 rank는 무엇이고 왜 32인가요?

rank는 가중치 변화량 `BA`의 저랭크 표현 크기입니다. A는 r×d_in, B는 d_out×r이고 r을 늘리면 용량과 비용이 함께 늘어납니다. 자료에서 r32·alpha64·dropout0.05를 확인했지만 rank sweep이 없으므로 32가 최적이라고 증명한 것은 아닙니다. [모델](04_model.md), 코드 전용 셀 4·7.

### Full fine-tuning보다 LoRA가 항상 좋은가요?

일반적으로 학습할 파라미터와 저장할 어댑터가 작다는 장점이 있습니다. 하지만 모델 본체의 로드 메모리는 남고 성능 우위가 보장되지는 않습니다. 이 자료에는 full fine-tuning 직접 비교와 개인 의사결정 근거가 없습니다. 프로젝트에서 사용한 설정을 설명하고 그 이상의 선택 이유는 확인 필요로 남깁니다. [모델](04_model.md), 초기 발표 슬라이드 2.

### 이미지 MD5로 나누면 누수가 완전히 사라지나요?

파일 바이트가 같은 이미지를 묶는 데 도움됩니다. 재압축·크롭·유사 촬영·질문 템플릿 누수는 탐지하지 못합니다. 코드가 그룹을 통째로 선택해 600행 이상에서 멈추므로 분모도 실제 실행으로 확인해야 합니다. dev 추가에서도 validation 해시와 같은 행을 제외합니다. [데이터](02_data.md), 코드 전용 셀 5.

### 공개 dev를 validation으로 썼나요?

제공 코드의 dev는 다수결로 학습에 추가한 파일입니다. 내부 validation은 train에서 사진 그룹으로 떼어 냅니다. 최소 3표, 합의율 0.5, 1위·2위 차이 1이 기준입니다. 2,097행 채택은 자료상 기록이고 현재 CSV로 재계산하지 않았습니다. [데이터](02_data.md), 최종 발표 슬라이드 5.

### Temperature scaling은 무엇을 바꾸나요?

네 보기의 TTA 집계 확률에 log를 취해 T로 나누고 softmax합니다. validation log-loss를 `[0.3,5]` 범위에서 최소화합니다. 단독 argmax는 보통 유지하지만 다른 뷰와 결합할 때 확신의 강도가 달라집니다. Gemma T3.36은 원본 설명값이지 현재 측정값이 아닙니다. [앙상블](05_ensemble.md), 코드 전용 셀 16·설명 셀 20.

### 왜 로그확률을 평균하나요?

코드 방식은 정규화된 가중 기하평균입니다. `P(c) ∝ ∏ q_v(c)^{w_v}`로 볼 수 있고 계열당 총 지분을 통제합니다. 매우 작은 확률의 영향도 있어 무조건 과신에 강하다고 할 수는 없습니다. 최종 가중치 합은 `3/12+2/8+1/4+1/4=1`입니다. [앙상블](05_ensemble.md), 코드 전용 셀 16·최종 발표 슬라이드 2.

### TTA가 이미지 뒤집기인가요?

이 프로젝트의 코드는 보기 순환입니다. Qwen TTA2는 s0·1, Gemma TTA2는 s0·2입니다. `agg[:,perm]`으로 원래 보기 위치에 복원하고 로그확률을 평균합니다. 부록에서는 TTA2가 s0보다 낮은 비교도 있어서 항상 도움이 된다고 말하지 않습니다. [앙상블](05_ensemble.md), 코드 전용 셀 8·12·14.

### 오답 Jaccard가 낮으면 좋은 뷰인가요?

오답 집합의 교집합을 합집합으로 나눈 값입니다. 낮으면 오답 겹침이 작지만 낮은 정확도의 뷰도 낮게 나올 수 있습니다. VARCO는 독립성이 높았지만 최종 구성에서 빠졌고, 학습 후 단독 정확도가 오른 경우에도 앙상블 −2문항으로 기록됐습니다. 정확도와 확률 결합까지 봐야 합니다. 빈 집합 처리는 원본 코드가 없어 확인되지 않았습니다. [앙상블](05_ensemble.md), 회고록 §1.

### Gemma 학습으로 LB가 +0.0024 올랐다고 말할 수 있나요?

기록은 그 값을 제시하지만 변경에는 Gemma LoRA 추가와 VARCO 제외, 계열 지분 변경이 포함됩니다. 학습만의 인과 효과로 단정하지 않습니다. 동일 구성에서 한 요소씩 바꾸는 ablation이 필요합니다. [실험](06_experiments.md), [앙상블](05_ensemble.md), 회고록 §1·2.

### 좋은 단독 모델이 왜 앙상블에 도움되지 않나요?

기존 앙상블의 남은 오답을 고치지 않거나 새 오답을 만들 수 있기 때문입니다. 후기 Gemma31B 단독 0.9767은 높지만 7구성 순증 0, Gemma2 epoch 단독 0.9683은 앙상블 −4로 기록됐습니다. 단독 점수 대신 paired 고침·망침을 함께 봅니다. [실험](06_experiments.md), 회고록 §3.

### 검증셋 과적합을 어떻게 생각하나요?

같은 600행 내외에서 뷰·프롬프트·온도·가중치를 반복 선택하면 가장 좋은 후보의 점수에 선택 편향이 생깁니다. Public LB 반복 피드백도 독립 최종 검증을 대신하지 못합니다. 발표의 5분할 교차 적합은 제공 코드로 확인되지 않습니다. 별도 holdout이나 nested 평가를 계획해야 합니다. [앙상블](05_ensemble.md), [배운 점](08_lessons.md), 최종 발표 슬라이드 5.

### 기억할 실패 실험 하나를 설명해 주세요.

받아쓰기 이식은 작은 validation subset에서 +2문항(p0.5)였는데 LB0.97140→0.97080으로 악화됐습니다. 작은 표본에서의 개선과 다른 평가에서의 이득을 구분해야 합니다. 가중치 무작위 탐색 LB0.7050도 기록돼 있지만 구현 오류인지 과적합인지 원인 로그는 없어 단정하지 않습니다. [실험](06_experiments.md), 설명 노트북 셀 23.

### 재도전한다면 무엇부터 하나요?

최종 Gemma LoRA 코드·예측 배열을 확보하고 동일 분할·행 ID를 고정하겠습니다. 그다음 학습 뷰 추가와 VARCO 제외를 나눠 검증하고 독립 holdout에서 평가합니다. 유사 이미지 누수와 표기 탐지 오류도 점검합니다. 이는 향후 계획이며 이미 수행한 성과가 아닙니다. [배운 점](08_lessons.md), [재현 안내](reproduction.md).

## 스스로 설명해 볼 복습 질문

1. 화면 보기 순서가 `[b,c,d,a]`일 때 화면 a의 점수를 원래 어느 보기에 더해야 하는가?
2. 단독 뷰의 argmax가 그대로인데 temperature가 앙상블 정답을 바꿀 수 있는 이유는?
3. Q·HR·G·GL의 뷰 수가 달라도 계열별 1/4을 유지하려면 각 뷰의 지분은 얼마인가?
4. 오답 Jaccard가 같은 두 뷰의 정확도가 다를 수 있는 예를 만들 수 있는가?
5. 37행에서 고침2·망침0을 관찰했을 때 다음 평가 없이 무엇까지 주장할 수 있는가?
6. Public 점수와 validation 점수, 단일 뷰와 전체 앙상블을 혼동하면 어떤 결론이 잘못되는가?
7. 사진 파일 해시가 달라도 같은 정보를 가진 이미지가 양쪽에 들어갈 수 있는가?
8. 최종 보고 0.97378과 제공 노트북 0.97140을 정확히 설명하고 누락된 자료를 말할 수 있는가?
