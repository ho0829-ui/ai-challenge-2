# 01. 문제 정의: 글자가 있는 장면의 4지선다 VQA

## 무엇을 맞히는가

VQA(Visual Question Answering)는 이미지를 보고 질문에 답하는 **과제**입니다. VLM(Vision-Language Model)은 이미지와 텍스트를 함께 처리하는 **모델 범주**입니다. VLM으로 VQA를 풀 수 있지만 두 용어는 같은 뜻이 아닙니다. 이 프로젝트는 자유로운 설명 생성보다 주어진 네 보기 중 하나를 선택하는 한국어 장면 텍스트 문제에 초점을 둡니다.

입력은 이미지 경로, 질문, `a/b/c/d` 네 보기입니다. 출력은 정답 보기의 소문자 한 글자입니다. 예를 들어, **실제 데이터가 아닌 설명용 예제**로 “메뉴판에서 국수 가격은?”이라는 질문과 `a=4,000원`, `b=5,000원`, `c=6,000원`, `d=7,000원`을 줄 수 있습니다. 모델은 글자 인식뿐 아니라 메뉴 이름과 가격의 연결도 판단해야 합니다. 원본 사진의 공개 권한을 확인하지 못했으므로 실제 이미지는 배포하지 않습니다.

근거: `D024_천천히꾸준히김상엽_base.pptx` 슬라이드 1·2, `vqa_solution_code_only.ipynb` 셀 5·8. [원본 대응](sources.md).

## 문장 생성 대신 선택지를 채점한다

코드는 프롬프트 마지막 위치의 다음 토큰 로짓에서 `a/b/c/d`에 해당하는 네 값만 읽습니다. 각 글자가 토크나이저에서 한 토큰인지 검사하고, 네 값에 softmax를 적용합니다. 긴 답변을 생성한 뒤 파싱하는 방식과 달리 형식 오류를 줄일 수 있습니다. 그러나 모델이 맞는 보기를 선택하는지와 출력 형식이 안정적인지는 별개의 문제입니다.

학습도 순열을 적용한 네 보기의 교차 엔트로피를 사용합니다. “답변 전체 문장을 잘 생성하는 목적”보다 실제 평가 대상인 보기 선택과 가까운 목적을 사용한 것입니다. 시각 근거를 정확히 읽는 능력이 자동으로 보장되는 것은 아닙니다.

근거: 코드 전용 노트북 셀 7의 `LETTER_IDS`, 셀 8의 `letter_logits`, 셀 9의 `F.cross_entropy`; 초기 발표 슬라이드 2.

## 평가를 어떻게 읽어야 하는가

내부 validation은 `argmax`와 정답 라벨이 같은 비율인 accuracy입니다. Public LB는 대회의 별도 평가 결과로 자료에 기록되어 있습니다. 정확한 대회 공식 채점 문서와 Private 평가 결과는 제공되지 않았으므로 확인 필요입니다. 내부 검증 정확도와 Public LB를 같은 문항에서 측정한 수치처럼 빼거나 더하지 않습니다.

원본은 사진 단위 약 600행 validation을 설명합니다. 실제 코드는 이미지 그룹을 통째로 넣다가 행 수가 `N_VALID=600` 이상이 되면 멈추므로 항상 정확히 600행이라고 보장하지는 않습니다. 실제 생성된 `val_y.npy`나 실행 출력이 있어야 해당 실행의 분모를 확정할 수 있습니다.

근거: 코드 전용 노트북 셀 5의 분할 루프·`acc_of`; 회고록 도입; 최종 발표 슬라이드 5.

## 제약이 접근에 준 영향

작은 글자, 가격과 항목의 연결, 같은 의미의 다른 표기, 문항 자체의 모호성이 문제로 보고됩니다. 더 큰 모델이나 더 많은 학습이 모든 오답을 해결하지 못했다는 것이 회고의 요지입니다. 이는 제공된 실험에 대한 관찰이지 VQA 전체에 적용할 법칙은 아닙니다.

GPU·데이터가 없는 현재 환경에서는 문서화와 CPU 함수 검증만 수행했습니다. 원본 GPU 학습 시간, 모델 다운로드 시간, 사용 비용은 실행 로그가 없으므로 새로 추정하지 않습니다. 원본에서 주장한 처리 속도도 [초기 접근](03_baseline.md)에서 기록의 범위를 구분합니다.
